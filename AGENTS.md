# AGENTS.md

Памятка для агента, разрабатывающего этот проект. Описывает, как здесь принято работать с документацией, тестами и «живыми» примерами (liveman), и какие грабли уже были наступлены.

Проект: `Aion-Aya` (ORM для Aion). Библиотеки `Aion`, `Aion::*` и `Liveman` лежат рядом в `/ext/__/@lib/` и уже установлены.

## Главное правило: мануал — он же тест

Документация ведётся в `lib/**/*.md` — **мануалах**. `liveman` превращает такой `.md` в:

1. тест `t/**.t` (блоки ```perl ``` исполняются);
2. POD, который вставляется в `__END__` соответствующего `lib/**.pm`.

Поэтому `lib/**.pm` **не редактируют вручную** в POD-части: правишь `.md` и перегенерируешь. В `.pm` допустимо менять только код (до `__END__`).

```sh
liveman lib/Aion/Aya/Query/Join.md -p    # -p = запустить через prove (меньше шума, чем yath)
liveman lib/Aion/Aya/Query/Join.md -c    # только компиляция/генерация, без запуска тестов
```

Типичный цикл: написать/поправить `.md` → `liveman … -p` → добиться PASS. Красный тест = плохой пример/документация, а не «нужно поправить тест».

Куда попадает тест: `t/` + путь `.md` без `lib/`, с точками между короткими частями. Например `lib/Aion/Aya/Query/Join.md` → `t/aion/aya/query/join.t`, а `lib/Aion/Aya/Adapter/Transform/SQL.md` → `t/aion/aya/adapter/transform/s-q-l.t` (имя `SQL` разбивается на `s-q-l`).

## Структура мануала

```md
!ru:en
# NAME

Модуль - краткое описание

# SYNOPSIS

```perl
...исполняемый пример...
```

# DESCRIPTION

Абзацы текста.

# FEATURES

## feature

Описание фичи.

# SUBROUTINES

## method ($arg)

Описание метода + пример.

# AUTHOR
# LICENSE
# COPYRIGHT
```

Правила оформления:

- **`SYNOPSIS` — только код, без поясняющих абзацев.** Описание выносится в `DESCRIPTION`. Так требуют правила POD (`SYNOPSIS` — это пример).
- **Заголовки `#`/`##` не переводятся.** Делай их английскими и, где возможно, просто операторами/именами: `## next`, `## @{ }`, `## &{ }`, `## < >`, `## inner_join ($field, $alias)`. Никаких «Перебор циклом».
- **Комментарии внутри кода не переводятся**, поэтому пиши их по-английски и делай тесты самодокументируемыми.
- Комментарий перед `sub`/`has` в `.pm` обязателен — и тоже по-английски.
- Шапка `AUTHOR`/`LICENSE`/`COPYRIGHT` — как в соседних мануалах; в `COPYRIGHT` подставляй имя своего модуля.

## `!ru:en` и перевод

Первая строка `!ru:en` включает перевод: liveman зовёт внешнюю утилиту `trans` (сейчас `/usr/local/bin/trans`) и кэширует перевод в `i18n/<путь>.ru-en.po`.

- Текст в POD после генерации будет **английским** — это нормально.
- Файл `i18n/**/*.ru-en.po` генерируется автоматически; коммить его вместе с мануалом.
- `trans` иногда падает (`[ERROR] Null response`). Тогда просто перезапусти `liveman` — со второго/третьего раза обычно проходит.
- Переводятся только текстовые абзацы; код, комментарии в коде и заголовки не трогаются.

## Синтаксис «живых» проверок

В блоках ```perl``` строка с `# <оператор> <ожидание>` превращается в ассерт. Утверждение должно стоять **на той же строке**, что и код (многострочный вызов + `# ->` не распознаётся).

| Оператор | Что проверяет |
|---|---|
| `# -> expr` | `is`: значения равны (строковое сравнение) |
| `# --> expr` | `is_deeply`: структуры равны |
| `# => expr` | строка через `qq`-эквивалент (`"$var"` без экранирования) |
| `# @-> сообщение` | код **должен умереть**, текст ошибки начинается с `сообщение` |

Пиши ожидания корректным Perl-выражением. Примеры:

```perl
$iterator->next          # -> 1          # is
$x ~~ Some::Type()       # -> ''         # пустая строка = не проходит проверку типа
$query->filter           # -> undef
$table ~~ Table::Column() # -> 1
$module->new             # @-> from required
```

Красный дифф вида `$diff = "{...}"` означает **получено лишнее** (`{...}` = append), `"[...]"` — **удалённое** (remove). Это подсказка, что сравниваешь не то (`ref` объекта вместо строки, лишний разделитель и т. п.).

## Как исполняется код примера

Код `##`-секций разбивается на **subtest** по заголовкам `#`/`##`: у каждого заголовка свой `subtest`. Значит:

- Переменные **не видны** из предыдущих `##`-секций — в каждой секции объявляй нужные заново.
- Пакеты (`package X { … }`), объявленные в одном блоке, видны и в следующих (это один файл).
- Секция `# SYNOPSIS` — отдельный `subtest`; `# NAME`/`# DESCRIPTION` — тоже (текст идёт комментариями).

Исполнение происходит в **временном каталоге** (`$TMPDIR/.liveman/<проект>/…`), в `@INC` добавляются настоящий `$PROJECT_DIR/lib` и локальный `lib` теста.

### Файлы-фикстуры: `Файл lib/X.pm:`

Блок, перед которым стоит строка `Файл lib/X.pm:` (или `File lib/X.pm:`), **не исполняется**, а записывается в файл `lib/X.pm` во временном каталоге до запуска теста. Дальше его можно подключить через `use X;`.

```md
Файл lib/ExEntity.pm:
```perl
package ExEntity;

use common::sense;
use Aion with => 'Aion::Aya';

presents 'books';

1;
```

Код:
```perl
use ExEntity;
```
```

Если после `Файл … является:` (со словом `является`/`is`) — файл **сверяется** с содержимым блока, а не пишется.

## Модели в примерах

Модель Aion объявляется через роль:

```perl
package My::Book {
	use Aion with => 'Aion::Aya';
	use Aion::Types;

	presents 'books';

	has id    => (is => 'ro', isa => Int, pk => 1, col => 1);
	has title => (is => 'ro', isa => Str, col => 1);
}
```

Важно:

- Подключать **именно** `use Aion with => 'Aion::Aya';`. Просто `use Aion::Aya;` не подмешивает аспекты `col`/`pk`, и `has … col => 1` умрёт с `not exists aspect 'col'`.
- Пакет с `use Aion with => 'Aion::Aya'` (внутри файла или в `{ }`-блоке) получает `has`/`presents` в **своей** области, поэтому аспекты видны.
- `use Aion::Types;` нужен, чтобы `Int`, `Str`, `Object[...]` были видны как типы.
- Модели через `Aion::Aya::Query`/`QueryBuilder` должны удовлетворять `ConsumerOf['Aion::Aya']` (то есть объявлены через эту роль), иначе будет `must have the type (ClassName & ConsumerOf['Aion::Aya'])`.
- Изредка проще подменить метаданные без объявления колонок: `$Aion::Aya::META{ExEntity}->{field} = { id => {name => 'id', type => 'col', col => {name => 'id'}}, … }`. Это допустимо для мануалов типа `Transform::SQL`, где проверяется сборка SQL, а не объявление модели.

### Ловушка `-u` vs `'-u'`

В Perl `-u` — это унарный минус от `$_`, а **не** строка `'-u'`. Тире-нотация (как `user => '-u'`) работает только когда это **строка в кавычках**. В примерах пиши `'‑u'`, `'-a'` и т. п. явно строкой.

### Классы-роли и `new`

`Aion::Aya::Iterator` и трансформеры объявлены ролями (`use Aion -role`), поэтому у них **может не быть** `new` до явной инициализации: `Some::Role->Aion::initialize`. Если конструктор доступен и работает — используй его; если нет — `bless {}, 'Some::Class'` в примере допустим, но лучше починить сам модуль, а не обходить.

## Что делать с `${\ ... }` и интерполяцией

В Perl «однострочная» интерполяция выражения — `${\ EXPR }`. Это позволяет собирать строку без `.`-конкатенации (которая на каждом шаге создаёт временную копию).

- `${\ $obj->method }` — подставить результат метода: `"… JOIN ${\$model->table} …"`.
- Для тернарника нужны **внутренние скобки**: `"${\ ($cond ? 'A' : 'B') }"`. Без них `?`/`:` съедают хвост строки в false-ветку (`LEFT JOIN …` прев��атился в ерунду).
- **Не путай** `${\ … }` с `${( … )}`: `${(…)}` Perl читает как скалярный блок, а не интерполяцию, и даёт пустую строку. Правильно: `${\ (…) }`.
- Обязательно прогоняй пример после такой правки — ошибки приоритета ловятся только тестом.

## Грабли liveman/POD, на которые уже наступали

- **Угловые скобки `<слово>` в тексте** liveman превращает в ссылку на metacpan (`<таблица>` → `[таблица](https://metacpan.org/pod/таблица)`), и получаются битые ссылки. Не пиши плейсхолдеры в угловых скобках в прозе; используй `{таблица}`, `{поля|*}` или обратные кавычки. `<Модуль::Имя>` — можно, это реальная ссылка.
- **Ожидание на отдельной строке не работает**: `$obj->call(\n …\n) # -> x` — нет. Держи вызов и `# ->` в одной строке.
- **`ref` объекта с перегрузкой** — это класс, а не `CODE`/`HASH`. Например `$generator = $iterator` (перегрузка `&{}`) остаётся `Aion::Aya::Iterator`.
- **`@$iterator` в `my $rows = @$iterator;`** даёт `scalar`, а не ссылку. Если нужен массив — `my $rows = \@$iterator;`.
- **Моки без роли** (`our @ISA = 'Aion::Aya::Adapter'`) не создают `new` и не проходят проверки типов. Для тестов «чистого» контракта иногда проще взять минимальную реализацию роли, а не наследование.
- **Пустые `has`/аспекты** и `col` требуют роли (см. «Модели в примерах»).
- **`isnt` — строковое сравнение.** Для проверки «новый объект» используй `Scalar::Util::refaddr`.

## Прочее

- Коммитить вместе: `lib/**.md`, перегенерированный `lib/**.pm`, `t/**.t`, `i18n/**/*.ru-en.po`.
- `cover_db/` в `.gitignore` — не коммить.
- Не оставляй отладочные файлы в `lib/`/`t/` (и не добавляй в индекс): удобнее держать их в `/tmp` или удалять после.
- Проверяй результат минимально широко: сначала `liveman <файл> -p`, затем `prove -Ilib -r t`, чтобы увидеть регрессии в соседних модулях.
- Часть тестов в репозитории красная исторически (например используют устаревшие фикстуры). Перед тем как «чинить» падение, проверь через `git stash`, что оно было и до твоих правок — и не приписывай себе чужое.
